Client
======

A :class:`~imgproxykit.Client` stores your imgproxy server's public address
and URL generation settings. Create it once and reuse it for different
source images and transformations.

.. _user-guide-docker:

.. tip::

    Start this container to try examples. Run and open a printed
    URL in your browser.

    .. code-block:: bash

        docker run -d --rm \
          --name imgproxy-guide \
          -p 127.0.0.1:8080:8080 \
          -e 'IMGPROXY_ALLOW_SECURITY_OPTIONS=true' \
          -e 'IMGPROXY_PRESETS=thumbnail=resize:fill:300:300,small=resize:fill:96:96' \
          ghcr.io/imgproxy/imgproxy:v4.0.0

    This server accepts unsigned URLs and enables the presets and security
    options used in the guide.

Build a URL
-----------

Create a client with your imgproxy server's address. Without signing
credentials, it generates unsigned URLs containing ``/unsafe/``; the server
must accept unsigned requests.

Call :meth:`~imgproxykit.Client.url` with the original image's URI as
``source``. The source must be accessible to imgproxy. Pass a
:class:`~imgproxykit.Transform` through ``transform`` to include processing
options:

API response. URL generation makes no network requests; imgproxy fetches
and processes the original when the generated URL is requested.

To generate a URL without explicit processing options, omit ``transform``:

.. literalinclude:: /examples/client/url.py
   :language: python
   :lines: 25-26

Imgproxy applies its server defaults.

.. tip::

    To shorten URLs with many processing options, set
    ``short_option_name=True``. This uses aliases such as ``w`` and ``q``
    instead of the full names used by default:

    .. code-block:: python

        client = Client('https://imgproxy.example.com', short_option_name=True)
        client.url(source, transform=Transform(width=300, quality=85))

    Options without a short alias keep their full names. Switching this
    setting changes URL paths and their signatures.

Sign URLs
---------

.. tip::

    Start this container to try the signing example on port 8081.
    Run the example and open the printed URL in your browser.

    .. code-block:: bash

        docker run -d --rm \
          --name imgproxy-guide-signed \
          -p 127.0.0.1:8081:8080 \
          -e 'IMGPROXY_KEY=736563726574' \
          -e 'IMGPROXY_SALT=73616c74' \
          ghcr.io/imgproxy/imgproxy:v4.0.0

    This server checks URL signatures using the key and salt from the
    example below.

Supply both ``key`` and ``salt`` when creating :class:`~imgproxykit.Client`.
Use the same hex-encoded values configured in your server's
`IMGPROXY_KEY and IMGPROXY_SALT
<https://docs.imgproxy.net/latest/configuration/options#url-signature>`__:

.. literalinclude:: /examples/client/signed_url.py
   :language: python
   :start-at: from imgproxykit

This client signs URLs generated by both :meth:`~imgproxykit.Client.url`
and :meth:`~imgproxykit.Client.variants`.

.. warning::

    Keep the key and salt in your application on the server. Send only the
    generated URLs to browsers and other clients. Use your own credentials
    when connecting to a production server.

Generate several URLs
---------------------

:meth:`~imgproxykit.Client.variants` accepts a mapping of names to complete
transformations and returns a dictionary of URLs for one source. Every URL
uses this client's configuration. See :doc:`variants` for defining,
reusing, and typing these mappings.

.. tip::

    Keep the server on port 8080 running for the remaining chapters.
    When finished, stop it:

    .. code-block:: bash

        docker stop imgproxy-guide

    If you also started the signing example, stop that container:

    .. code-block:: bash

        docker stop imgproxy-guide-signed
